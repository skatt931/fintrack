# Finance PWA Visual Direction Brief

Implements GitHub issue `#21`.

## Direction

**Calm utility with character.**

The app should feel like a personal finance cockpit that was designed for one real person, not a generic SaaS template. It should be:

- light, warm, and readable first
- compact enough to stay useful
- expressive through typography and rhythm
- memorable through a strong illustrated identity system

## Primary user signals

The product should prioritize these signals above everything else:

1. `Safe Limit`
2. `Today Spend`
3. current active period in a human-readable format

`Income`, `Expenses`, and `Balance` stay important, but no longer own the first visual focus.

## Visual ingredients

- **Theme:** predominantly light, with paper-like surfaces and dark-ink text
- **Typography:** characterful display face for headlines + clean body face for dense data
- **Spacing:** calmer vertical rhythm, fewer cramped control clusters
- **Shapes:** rounded, tactile surfaces with soft depth
- **Accents:** restrained warm/coral/gold emphasis instead of neon contrast
- **Motion:** smooth, subtle, confidence-building transitions

## Mascot direction

The mascot should feel:

- clever, calm, slightly playful
- more like a signature or guide than a cartoon overload
- usable in tiny accents, empty states, headers, and onboarding moments

The mascot should not block dense finance data or become the main focus on operational screens.

## Must have

- human-readable date and period language
- clear hierarchy between primary metrics and secondary analytics
- shared visual system across shell, cards, filters, sheets, and empty states
- mobile-first readability

## Must avoid

- dark generic fintech styling
- too many equal-weight cards fighting for attention
- technical labels shown raw where a human format is possible
- decorative illustration that competes with data
- playful choices that weaken trust or clarity

## Guardrails for AI implementation

- prefer one distinctive idea over many scattered embellishments
- use shared tokens instead of one-off colors
- keep controls readable at small mobile widths
- preserve drill-down behavior and interaction reliability
- new visuals should reduce noise, not only repaint it
